Solution Architecture

Exchange (api.codetoimpact.sg) | |—— SSE feed (price, trade, session, announcement) | | | [Python Trading Bot] [JS Dashboard] | • Event queue (bounded) • EventSource connection | • Worker thread • Real-time DOM updates | • Strategy router • Stale-value clearing | • Risk engine • Kill switch button | • OrderManager | | • Control API (:8092) <———-+ | | |—— REST API (orders, portfolio, instruments) | | | [MCP Read Server] [Dashboard server.js] | • get_portfolio • Key-injecting proxy | • get_positions • /exchange/* → API | • get_pnl • /bot/* → :8092 | • get_session_summary | • REST facade (:8090)

Three isolated processes. API key never reaches the browser. Dashboard proxies all authenticated requests through server.js.

Architecture Choices

Event Queue Decoupling

SSE events go into a bounded queue. Trading logic runs in a separate worker thread. This prevents REST calls from blocking feed ingestion and eliminates the 300-calls/30s burn rate.

Key-Injecting Proxy

server.js injects X-API-Key into proxied requests. The browser never sees the team key. Dashboard fetches go to /exchange/* which the proxy routes to the real API.

MCP with REST Facade

MCP server exposes both MCP protocol (for AI tools) and a REST facade (for the browser). Dashboard calls REST directly for P&L; AI panel would use MCP tools.

Session Lifecycle Awareness

Bot detects session ID changes and clears all state (price history, pending orders, cached positions). Prevents stale data from leaking between trading windows.
